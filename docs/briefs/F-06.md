### 3.2 What the test bed does

- **Gives every package fixed inputs for time, files, processes, the network and the outside world**, as Go
  implementations of F-04's interfaces, so a unit test touches nothing of the machine (REQ-RM-1253, REQ-TS-0172).
- **Runs network tests in throwaway namespaces** joined by virtual cables, as the PC user, without root
  (REQ-RM-1353, REQ-TS-0199), with fake servers for DHCP, PPPoE discovery and session, DNS, HTTP(S), iPerf3, RMBT,
  STUN and the other services of 5.5.
- **Runs what needs a real kernel feature the PC does not give** (Wi-Fi with `mac80211_hwsim`, the kernel PPP data
  path, procd, the target CPU) in one QEMU guest at a time, under the lock, with at most 512 MB (REQ-WP-0029).
- **Lets each test declare where it must run** and reports every test that did not run, with the reason, instead of
  passing silently (5.7).
- Inputs: test code, recorded exchanges (F-07's `spec/vectors/`), checked base images (from the image records),
  environment knobs. Outputs: Go test results, one line per step, a `testbed.tsv` (tier, test, where, result,
  reason, profile). States of a guest run: waiting for the lock, booting, ready, running step n, powering off,
  done/failed/not run. Timings and limits: section 5.6.5. Errors: fail closed (a missing tier is "not run", never
  "pass"; a corrupt image, a held lock past its wait, too little memory: "not run" with the reason).

Where Python is wrong (QB 6): Python faked by monkeypatching module globals (`mock.patch.object(adblock_mod, "time",
...)`, `tests/_box_isolation.py@ad3758c:13-14` rewriting `runner.MEASURE_LOCK` at import), which works only while the
patched name is the one read; correct is dependency injection of a clock, paths and runner through F-04's interfaces,
so there is nothing global to patch. Python ran unit tests "as root inside VM-D13" (TESTING 20) on a long-lived VM;
correct is a throwaway guest from a checked image with `snapshot=on` per run. Python kept its VM scripts outside the
repository (TESTING 399, KF-0265); correct is everything in the repository.

| system-tool calls (REQ-CT-0003: full error handling, tool missing) | `fakeexec`: argv-keyed recorded responses, missing tool, tool outside `PATH`, timeout, non-zero exit |
| event and log record | `fake/events` sink with assertions (own-action windows of C-07 are tested with it) |
| status file formats, configuration format, database schema | not faked: tests use the real C-01/C-02 code on throwaway paths |

**Needed and not in F-04's row, so listed under Blocked (section 11):** a **clock** contract and a **paths**
contract. Proposed shapes (for F-04 to accept, change or reject; F-06 then fakes whatever F-04 fixes):

```go
// Proposed for F-04 (not defined by F-06). Mono is an opaque monotonic instant: durations only, never a date.
type Mono int64 // nanoseconds since an arbitrary origin; comparable only within one process run

type Clock interface {
	Mono() Mono                      // monotonic reading; every duration, interval, timeout and RTT comes from here
	Wall() time.Time                 // wall clock with the box's location; only for stored timestamps (KF-0052)
	NewTimer(d time.Duration) Timer   // fires after d of monotonic time
	NewTicker(d time.Duration) Ticker
	Sleep(ctx context.Context, d time.Duration) error // monotonic; returns ctx.Err() when cancelled
}

// Paths: every file and socket a component uses (config, live and snapshot database, locks, state files, caches,
// crash and bundle folders, runtime sockets) comes from one table (KF-0290, KF-0134).
type Paths interface { Path(name PathName) string }
```

Why a separate `Mono` type and not `time.Time`: a `time.Time` made by a fake carries no monotonic reading, so
`t.Sub` silently falls back to wall time; a distinct type makes "duration from the wall clock" a compile error.
The real `Clock` belongs to C-05 (REQ-RM-1056, "monotonic time helpers", work plan 124); F-06 provides the fake and
a conformance suite both must pass.

### 5.1 Fake clock

5.1.1 `FakeClock` implements F-04's `Clock` (proposed in 4). It holds a monotonic instant (`Mono`) and a wall
instant with a `*time.Location`. It never sleeps and never reads the real clock.

5.1.2 Operations (each one locks one mutex; timers are a min-heap ordered by due `Mono`, ties by creation order):

| Call | Effect |
| :--- | :--- |
| `New(start time.Time, loc *time.Location)` | wall = `start`, mono = a fixed non-zero origin (so code that wrongly assumes "mono 0 = boot" is caught) |
| `Advance(d)` | moves mono and wall by `d`; fires every timer due on the way, in order, each at its own instant (wall and mono at the moment of firing equal the due time) |
| `StepWall(d)` | wall only, forward or backward (NTP step, the WSL +1 h jump of 2026-11-10, a battery-less Pi booting in 1970); timers do not fire |
| `SetLocation(loc)` | zone change (first-start setup, QB 9) without moving the instant |
| `BlockUntilWaiters(n, limit)` | waits (real time, bounded by `limit`, default 5 s) until `n` goroutines are blocked on this clock: the only real-time wait, so a test does not race a goroutine that has not reached its `Sleep` yet |
| `Waiters()`, `Pending()` | for assertions |

5.1.3 Time zones: `testbed/clock` imports `time/tzdata` (embedded zone database), so test zones never depend on the
host's `/usr/share/zoneinfo`. Fixtures: `UTC`, `Pacific/Chatham` (+12:45/+13:45, the zone of F-00's run B),
`America/St_Johns` (-3:30, DST), `Asia/Kathmandu` (+5:45), `Australia/Lord_Howe` (30-minute DST),
`Europe/Berlin` (DST gap and overlap at 02:00/03:00), and helpers `DSTGap(loc, year)`, `DSTOverlap(loc, year)` that
return instants found by scanning the zone (no hard-coded dates). Whether `nmbd` itself embeds tzdata is C-10's and
P-11's decision, not this one.

5.1.4 Boot-relative time: `FakeClock.Mono()` starts at a fixed origin, not 0, and `fakesys` serves `/proc/uptime`
from the fake clock, so "the first minute after boot" (catalogue 7) is a test input (`WithUptime(30*time.Second)`).
For a program that is not ours (an engine binary, a tool) the same is done for real in the netns tier with a
**time namespace**: `CLONE_NEWTIME` with negative `monotonic` and `boottime` offsets written to
`/proc/self/timens_offsets` before the first child starts; checked on this PC (8.1: a static Go binary saw
`CLOCK_MONOTONIC` = 30 s). A time namespace cannot move `CLOCK_REALTIME` (`time_namespaces(7)`), so wall steps for
foreign programs are not possible without root and are not offered.

5.1.5 `tools/clockjump`: the dev-setup check of REQ-DV-0008, correctly: sample wall and monotonic every 10 ms for
30 s **of monotonic time measured from a fixed start**, count steps where the two differ by more than 0.5 s, print
`clock jumps in 30 s: N` and exit 1 when N > 0. The Python document's loop reassigns the variable it uses as its end
time, so it never ends (8.1, Q3). The gate prints its result in `environment.tsv` (integrator change, 5.10).

5.1.6 Real `Clock` conformance (with C-05): a suite `conformance.Clock(t, factory)` checks ordering, timer firing,
cancel, ticker drop semantics, `Sleep` cancel; it runs on the fake (fast) and on C-05's real clock (short real
durations, under 1 s total).

### 5.2 Host isolation: paths, writes, logs, environment, capability profiles

5.2.1 `host.Paths(t)` returns F-04's `Paths` with every entry under `t.TempDir()` (sockets under a short directory,
see 5.6.5 on the 108-byte limit). There is no fallback to a system path; asking for an unknown name fails the test.

5.2.2 Write guard: `host.Guard(t)` records the content of `HOME` and `TMPDIR` (F-00 already gives each run fresh
empty ones) and fails the test in `t.Cleanup` when anything was created there outside `t.TempDir()`. F-00's
`nmb_hermetic` (F-00:`tools/lib.sh:200-208`) deletes the folders without checking them; section 5.10 asks the
integrator to fail the run when they are not empty (KF-0290).

5.2.3 Log guard: `host.Secrets(t)` makes obviously fake secrets (`reserved.Token(n)`, e.g. `test-token-0000…`) and
fails the test if one of them appears in captured logs, events, bundles or error strings (REQ-CT-0017; the masking
itself is C-04's).

5.2.4 Capability profiles (REQ-WP-0154): `fakesys.Profile` = file tree + tool table + init system, one per base from
the records: `openwrt-25.12` (BusyBox `ip` without `-br`, procd, `udhcpc`, no `iw`/`hostapd`, `nft` 1.1.6: I-01 §7),
`debian-13` (full iproute2 6.15, systemd 257, `dhcpcd-base`, `nft` 1.1.3: I-06 §7), and the edge cases "tool
outside `PATH`" (roadmap 686), "tool missing", "other init". Each profile names the record and section it came from.

5.2.5 Environment guard: `host.Env(t)` clears `NMB_*` and proxy variables for the test and fails when product code
reads an environment variable the test did not set (through F-04's config, never `os.Getenv` in components:
`hermeticcheck`).

### 5.3 Fakes of F-04's interfaces and the recorded command runner

5.3.1 Each fake is a type with a compile-time assertion `var _ <contract>.<Iface> = (*Fake)(nil)` (KF-0074: a
changed interface breaks the build of the fake, not a test at run time).

5.3.2 Conformance suites (`internal/testbed/conformance`): for each F-04 interface a function
`<Iface>(t, impl)` with the behaviours both the fake and the real implementation must show (errors as typed values,
missing tool, empty results, ordering). The real implementation's package runs the same suite in the netns or guest
tier. A fake that passes the suite cannot return an invented shape (REQ-TS-0205, REQ-CT-0013).

5.3.3 `fakeexec`: a `Runner` (F-04's system-tool contract) whose responses are keyed by the exact argv; each
response file holds stdout, stderr, exit code, duration and a `source:` line (the record and command it was captured
from, for example "I-01 §7, guest `nft --version`"). An unknown argv fails the test (never a default success). Built-in
cases: missing binary, not executable, timeout, killed, output larger than the caller's limit.

5.3.4 Wi-Fi fake: a regdomain change is recorded, and a test that did not declare `ExpectRegdomainSet(cc)` fails at
cleanup (REQ-CL-0230, KF-0051).

### 5.4 Namespace tier: user and network namespaces with virtual cables

5.4.1 Entry: `netns.Run(t, func(tb *netns.Bed))`. If the test is not yet inside a test-bed namespace, it re-executes
the test binary as `<binary> -test.run '^<TestName>$' -test.count=1` with `SysProcAttr{Cloneflags:
CLONE_NEWUSER|CLONE_NEWNET, UidMappings: 0→caller uid, GidMappings: 0→caller gid}` and a marker variable, and
reports the child's result as the test's. Inside, the process is uid 0 **only in its own user namespace**
(capabilities over that namespace and its children, none over the host). Checked on this PC (8.1): a Go child made
this way saw uid 0, opened NETLINK_ROUTE and could `unshare(CLONE_NEWNET)` again; inside F-00's offline wrapper
(mapped back, no capabilities) a nested user+net namespace still works.

Fail closed: before creating anything, the bed reads `/proc/self/uid_map`; if it is the initial namespace's map
(`0 0 4294967295`) it refuses (`TestRefusesInitialUserNamespace`), so even when started by real root it can never
change real interfaces. It also refuses when the real uid outside is 0 (KF-0001).

5.4.2 Nodes and cables: a node is a network namespace held by an open file descriptor (made on a locked OS thread
with `unshare(CLONE_NEWNET)`, fd from `/proc/thread-self/ns/net`). Code runs "in" a node with `tb.Node("lan").Do(fn)`
(locked thread, `setns`, back). A fake server runs in a node in its own goroutine on its own locked thread, or as a
child process started inside the node for programs that are not ours (QB 6B.5 third-party engines).

| Builder call | Kernel object (all made by netlink from inside the namespace) |
| :--- | :--- |
| `tb.Node(name)` | network namespace, `lo` up |
| `tb.Cable(a, ifA, b, ifB)` | veth pair, ends moved by `IFLA_NET_NS_FD` |
| `tb.Bridge(node, name, ports...)` | bridge, ports enslaved, VLAN filtering optional |
| `tb.Addr(node, if, prefix)`, `tb.Route(node, dst, via)` | address, route |
| `tb.Pull(cable)`, `tb.Plug(cable)` | peer down/up (the other end shows NO-CARRIER: a pulled cable for N-01's hot-plug) |
| `tb.Impair(node, if, netem)` | `tc qdisc netem` delay, jitter, loss, rate, reorder (checked on this PC, 8.1) |
| `tb.Counters(node, if)` | `IFLA_STATS64` rx/tx bytes and packets (REQ-TS-0177) |
| `tb.Tap(node, name)` | tap device for a guest NIC (5.6.4) |
| `tb.WithTimeNS(offsets)` | child process in a time namespace (5.1.4) |

Standard topologies (functions, each used by several packages): `Lan(t)` (box + LAN client), `RouterBox(t)` (WAN
cable to an "ISP" node with fake DHCP/PPPoE/DNS/HTTP and an "internet" node behind it; LAN bridge with clients),
`BridgeBox(t)` (two ports bridged, client and router on either side), `TwoUplinks(t)` (wired + "USB" uplink for
failover), `RogueDHCP(t)` (second server on the LAN, REQ-TS-0200).

5.4.3 `testbed/nl`: a minimal rtnetlink and tc writer: RTM_NEWLINK (veth with peer, bridge, dummy, vlan, macvlan,
tap via `/dev/net/tun`), RTM_SETLINK (up, down, master, netns), RTM_NEWADDR, RTM_NEWROUTE, RTM_GETLINK with
`IFLA_STATS64`, RTM_NEWQDISC netem. No host tool is run (`ip` and `tc` are not needed, REQ-CL-0234). Netlink is
host byte order: `binary.NativeEndian`; attribute lengths and `NLMSG_ALIGN`/`RTA_ALIGN` to 4 bytes; addresses in
network order. Test-only; product netlink is N-01's (question Q6 on the duplication).

5.4.4 What the PC kernel gives the namespace tier, and what needs a guest (from 8.1):

### 5.6 QEMU guest runner

5.6.1 One run = one guest, one lock, one throwaway disk. The runner takes the lock first and keeps it to the end:
`flock(2)` `LOCK_EX` on `NMB_QEMU_LOCK` (default `$HOME/nmb-work/qemu.lock`, the file every agent on this PC uses),
waiting at most `NMB_QEMU_LOCK_WAIT` (default 30 min); when the wait runs out the run is "not run: lock held"
(never a second guest). The lock fd is inherited by nothing but QEMU's wait; it is released by the kernel when the
runner exits, also on a crash (I-01 run 3: lock free after SIGTERM). While this brief was written, other packages'
guests held the lock for more than ten minutes at a time (8.1), so the wait is normal, not an error.

5.6.2 Profiles (data files in the repository; values from the records):

| Profile | Base (record) | Machine | Firmware / boot | Accel | Memory, CPUs |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `openwrt-x86-64` | squashfs combined-efi (I-01 §1, §12) | `q35`, `-cpu host` (KVM) or `max` (TCG) | OVMF code read-only + a copy of the vars file per run | KVM when usable, else TCG | 256 MB, 1 vCPU (I-01 used 256; 512 allowed) |
| `openwrt-armv8` | squashfs combined-efi (I-02 §12) | `virt`, `cortex-a72` | `QEMU_EFI.fd` (`qemu-efi-aarch64`) | TCG `thread=multi` | 512 MB, 2 vCPUs |
| `openwrt-armv7` | squashfs combined-efi (I-03 §12) | `virt,highmem=off`, `cortex-a15` (LPAE) | the tree's `u-boot.bin` (copy per run); or the initramfs kernel by `-kernel` (I-03 run 3) | TCG `thread=multi` | 512 MB, 2 vCPUs |
| `debian-amd64` | mmdebstrap build "B" of I-06 (§12): kernel 6.12.107, hwsim module, Landlock, hostapd 2.10, wpa_supplicant, iw, ppp | `q35` | direct kernel boot (`-kernel`, `-initrd`, `-append root=/dev/vda … console=ttyS0`, `systemd.mask=serial-getty@ttyS0.service`, I-06 run 1 lesson) | KVM when usable, else TCG | 512 MB, 1 vCPU |

Each profile names the image file, its SHA-256 from the record, the record and its commit. The image is checked
before every run (SHA-256 of the file; a cached result keyed by device, inode, size and mtime is allowed). The base
image is never written: the system disk is attached with `snapshot=on` (writes go to a temporary overlay QEMU
deletes). A Debian arm64 profile (build "C" of I-06) is added when it has been booted once (not done in I-06).

5.6.3 Accel: KVM is used when `/dev/kvm` opens read-write for the runner; otherwise TCG, and the result line says
`TCG (KVM not usable: <errno>)`. On this PC (8.1) the user is in group `kvm` since 06:58 today but sessions started
earlier do not carry the group, and a `setfacl` grant was reset when the device node changed at 12:27; `sg kvm -c`
gives access. The runner does not call `sg` itself (no host tool); `tools/guestrun` documents `sg kvm -c` and the
gate script may use it (question Q2 for a permanent fix). ARM guests always use TCG on this x86 host.

5.6.4 Networks. Default: two QEMU user-mode networks with `restrict=on` (no outside access), LAN
`198.51.100.0/24` and WAN `192.0.2.0/24`, MACs `02:00:00:<profile>:<run>:<nic>` (from I-01..I-03). For tests that
cable a guest to fake servers or to other nodes: QEMU is started **inside a netns test bed** and its NICs are taps
there (`-netdev tap,ifname=…,script=no,downscript=no`); the taps are ports of the topology of 5.4, so a guest's WAN
port meets the fake ISP node and its LAN port meets namespace clients, all without root (taps work in the user
namespace, and QEMU with KVM started inside `unshare -rn` under `sg kvm`, with a tap made there as its third NIC: the
guest saw `eth2` and the tap counted 250 bytes from it, 8.3). Guest-to-guest cables are not needed while only one
guest runs.

5.6.5 Control and limits:
- **Serial console** on a Unix socket with a **short relative path** (`serial.sock` in the run folder, QEMU started
  with that folder as working directory): an absolute path over 107 bytes is refused by QEMU ("UNIX socket path …
  is too long"), seen on this PC (8.1).
- **Driver in Go** (no Python): waits for byte markers (never character offsets: I-01 run 2's UTF-8 offset bug),
  sends input in 32-byte pieces with 50 ms gaps (I-01 run 3: a 500-character line was cut), wraps each step as
  `<cmd>; echo <MA''RK><n>=$?` with a marker random per run (so console text from the guest cannot fake a result),
  split by quotes in the typed line so that the console's echo of the input never contains the marker itself (the
  trial driver of 8.3 matched its own echoed command and lost the result); after the marker it looks for the prompt
  in the bytes already read before reading more; reads with a bounded buffer (1 MiB per step; more is an error).
- **Time limits** (all knobs, validated): lock wait 30 min; console ready: x86-64 KVM 120 s, x86-64 TCG 240 s, ARM
  TCG 600 s (I-02: 76 s to the console, `init complete` by 288 s; I-03: 62 s, `init complete` 420-670 s); each step
  its own limit (default 120 s) and one printed line (REQ-TS-0208); whole run 45 min.
- **Clean shutdown**: `poweroff`, then wait for `reboot: Power down` and QEMU exit 0 within 120 s; else SIGTERM,
  then SIGKILL after 10 s, and the run is reported `unclean` (its test results still count, the shutdown is a
  finding).
- **Memory**: the profile's memory must be ≤ 512 MB (the runner refuses more) and `MemAvailable` must exceed it by
  200 MB at start, else "not run: memory" (at the time of 8.1 about 680-1,000 MB were available).
- **Readiness**: a profile may name a readiness probe (OpenWrt: `ubus call system board`; Debian: `systemctl
  is-system-running --wait`) before tests start.

5.6.6 Inside the guest:
- **Files in**: per profile. armv8 and armv7: a read-only 9p share of the run's input folder (`-virtfs
  local,…,security_model=none,readonly=on`; 9p is built into those kernels, I-02 §4, I-03 §12). **x86-64 OpenWrt: no
  9p** (`mount -t 9p` failed with "No such device" in the trial of 8.3; `kmod-fs-9p`/`kmod-9pvirtio` are not in the
  image), so that profile uses a read-only FAT data disk made with `mformat`/`mcopy` (`kmod-fs-vfat` is in the image,
  I-01 §10; the method of I-02, I-03). Debian: 9p to verify (not checked in I-06); FAT disk as the fallback.
- **Results out**: a raw "results disk" (`-drive …,format=raw` of a fixed size, e.g. 16 MiB, zero-filled); the guest
  writes one tar archive to the device (`tar -cf /dev/vdX …`; BusyBox `tar` is present, I-03 §7); the PC reads it
  with Go's `archive/tar`, rejecting absolute paths, `..`, links and device entries, and capping sizes. No writable
  9p share (not tried, and it would let the guest write into the PC's folder).
- **Tests**: the guest tier cross-builds the package's test binary for the guest's architecture (`go test -c`,
  `CGO_ENABLED=0`), puts it in the 9p share, runs it as the guest's root (`-test.v -test.count=1`, REQ-TS-0010; the
  guest is thrown away), and its `-test.v` output and the result tar come back.
- **Radios**: `guest.Radios(n)` loads `mac80211_hwsim radios=n` (REQ-TS-0008 asks three). Debian: the module is in
  the kernel package and gave two interfaces with the default (I-06 §4). OpenWrt: the module is not in the images;
  `kmod-mac80211-hwsim` and its dependencies (`kmod-cfg80211`, `kmod-mac80211`, compat) installed offline from the
  prepared cache (5.6.8) by `apk add` from a local repository folder on the 9p share, checked with the image's own
  trust key (`/etc/apk/keys/openwrt-25.12.pem`, I-02 §6), since the packages are the release's signed ones; never
  `--allow-untrusted` (I-02 §9a showed them loading from the feed: two radios). `hostapd`/`wpad`, `iw`, `wpa_supplicant` come
  from the cache the same way. Every hwsim result is marked simulated (REQ-TS-0011).

### 5.7 How a test declares where it runs, and the not-run report

5.7.1 Tiers: `unit` (default: PC user mode and QEMU user mode, F-00's runs A-G), `netns` (amd64 on the PC, new
run N), `guest:<profile>` (run Q), plus features `hwsim`, `kvm`, `kernel-ppp`, `procd`, `systemd`, `landlock`.

```go
func TestFirewallLanReachesSSH(t *testing.T) {
	tier.Need(t, tier.Netns)                     // skipped with a recorded reason outside the netns run
	...
}
func TestAccessPointWPA3(t *testing.T) {
	tier.Need(t, tier.Guest("debian-amd64"), tier.Feature("hwsim"))
	...
}
```

5.7.2 `tier.Need` reads `NMB_TESTBED_TIERS` (set by the gate per run; validated list) and, when the tier is not part
of this run, calls `t.Skip` with one machine-readable line: `NMB-NOT-RUN tier=<tier> feature=<f> test=<name>
reason=<why>`. A plain `t.Skip` without `tier.Need` is refused by `hermeticcheck` (no silent skips).

5.7.3 Reporting: the gate runs `go test -json` and `tools/testbed-report` (part of `tools/guestrun`) collects
`NMB-NOT-RUN` lines into `testbed.tsv` and the summary: "not run" tests are listed by tier and reason, never counted
as passed. A test that is declared for a tier and did not run in that tier in the package's gate leaves its
requirement ids without proof (work plan 2.4); the gate shows them. Results of the netns and guest tiers carry
`simulated` and the profile (image hash, accel, kernel) (REQ-TS-0011, REQ-CT-0002).

5.7.4 Where each tier runs: unit everywhere (also on the box in P-02's sandboxed test run); netns on the PC (amd64)
and inside guests; guest on the PC (or a rented server, REQ-WP-0037); never on the measuring box.

### 5.8 `tools/hermeticcheck`

A `go/analysis` checker over non-test product files (and over tests where stated): fails on `time.Now`, `time.Sleep`,
`time.After`, `time.Tick`, `time.NewTimer`, `time.Since` outside C-05's clock implementation; `os/exec` outside
F-04's runner implementation; `os.Getenv` outside the configuration loader; imports of `internal/testbed` from non-test
files; `t.Skip`/`t.SkipNow` in tests without `tier.Need`; literal IP addresses, MACs and host names in tests that are
not from `testbed/reserved` (complementing F-00's privscan). The allowed places are a short list in the checker,
each with its reason. Wiring into `tools/analyse.sh` is an integrator change (5.10).

### 5.9 Byte order, 32-bit, resources

- Byte order: netlink native (explicit `binary.NativeEndian`), every protocol fake big-endian on the wire
  (`binary.BigEndian`), tar and results parsing by the standard library. 32-bit: the clock's `Mono` is `int64`
  updated under a mutex (no unaligned 64-bit atomics on arm v7 and mips); netlink structs packed by hand, no
  `unsafe` casts.
- Resources on the PC: a namespace costs a few MB; the netns run uses `-p` = `NMB_GATE_JOBS` (default 2); fakes
  hold at most a few MB of buffers. A guest: 256-512 MB and QEMU's own memory (another package's 512 MB KVM guest had
  401 MB resident two minutes after start, `ps` during 8.1; resident memory grows as the guest touches its RAM, so
  the 200 MB margin of 5.6.5 is on top of the full guest size). Pi 4 budget: the test bed is not shipped in `nmbd`
  (test-only code); its unit-tier helpers must still finish in the arm64 user-mode run within ten times the amd64
  run's time (a limit to measure in F-06's own gate, not yet measured).

| Outside input | Where | Validation / handling |
| :--- | :--- | :--- |
| Environment knobs (`NMB_QEMU_LOCK`, `…_WAIT`, `NMB_TESTBED_CACHE`, `NMB_TESTBED_TIERS`, `NMB_GATE_JOBS`) | runner, tier | absolute paths of plain characters, lock outside the repository; durations by `time.ParseDuration` within limits; tier list from a fixed set; a bad value is an error, never a default |
