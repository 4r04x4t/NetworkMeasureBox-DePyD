## Proposed package changes

1. **NEW: P-14 Maker's firmware round trip** (roadmap 6B.3 points 2-3 and the stock part of the safety rules, line 565
   bootloader rule). Upload check of a maker's file against model and revision, the plain warning, the per-target write
   method, the optional online fetch from the maker's own address with verification, the recovery path per target, and
   the round-trip test on each supported router. Reason: P-02 owns NMB's own signed updates, A/B slots and rollback,
   which are step 1 on the PC and Pi 4; going back to stock firmware needs per-device research and tests on real
   routers, which are step 2. Keeping it in P-02 would make P-02 too big and would block P-02's acceptance in step 1.
   The generic safety rules (never another model, bootloader untouched, every step logged) stay in P-02 with P-14 as
   "Also in".
2. **NEW: T-01 First router backends, TL-WR1043ND v1 (step 2)**: `ath79` switch (RTL8366RB) and `ath9k` Wi-Fi
   backends, `procd`/`fw4` service and firewall backends, flash layout, the C11/musl build within 8 MiB flash and
   32 MiB RAM, the C code base ported from Go (6B.8 point 6), optional UPX. Reason: the work plan has only I-10 (image
   analysis) for step 2; the roadmap's step 2 also writes code, which no package owns. Further routers would get T-02...
   when the owner sets their order.
3. **Rows for step 2 go to X2-01** (round 1): rows that concern only the C code base or only router targets are owned by
   `NEW: X2-01 Step-2 router tiers`, as in `roadmap-1-507.md`, with the step-1 package under *Also in*: REQ-RM-1080,
   -1095, -1201, -1319, and the C halves split from mixed rows (REQ-RM-1451 from -1074, -1452 from -1077, -1453 from
   -1254, -1454 from -1376, -1455 from -1409). REQ-RM-1349 stays with P-04, because OpenWrt x86-64 and `armsr` are step-1
   QEMU targets.
4. No split proposed for rows of this range beyond the above. Note for the register owner: P-04 (sandbox) and P-02
   (updates) carry many requirements from this range (P-04: 6B.5 complete; P-02: 6B.3, 6A updates, 7D fixes); their
   analysts should check the size rule of work plan section 3 and split if the brief exceeds one sitting
   (for example P-04a service profiles, P-04b third-party/upload sandbox and user control).
