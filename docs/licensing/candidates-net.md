# Licence candidates: networking and system libraries

Package LIC-01, scout "net". Work plan section 7 point 9 (the licence of the whole follows from the components; until
it is fixed, no dependency is taken whose licence would rule out an open licence) and roadmap 6B.3A (every
component with its licence, origin and version; built in or only run). This is a candidate list, not
`docs/DEPENDENCIES.md`: nothing here is accepted yet, and no row here is in a `go.mod`.

## How this was checked (2026-11-11)

- **Version:** the latest version the Go module proxy answers for `https://proxy.golang.org/<module>/@latest`
  (tag, commit time, commit hash from its `Origin`), read 2026-11-11. Upstream C projects: the highest release tag
  of `git ls-remote --tags` on the project's own repository, then a shallow clone of that tag (commit and date below).
- **Licence (first source):** the licence file inside the module zip of that exact version (Go module cache, filled
  through the proxy), classified by its text and hashed with SHA-256 (the same hash `tools/depcheck` checks).
  Per-file `SPDX-License-Identifier` lines and licence headers in the `.go` / `.c` files were grepped for
  GPL/LGPL/AGPL/MPL and for files under another licence.
- **Licence (second source):** pkg.go.dev licence detection, `https://pkg.go.dev/<module>@<version>?tab=licenses`,
  read 2026-11-11. Both sources agree for every Go row; differences in detail (files under a second licence) are
  written in the row.
- **Own dependencies built in:** a throwaway module per candidate in the session scratchpad (outside the repository),
  `GOFLAGS=-mod=mod GOTOOLCHAIN=go1.27.4`, `go get <module>@<version>`, `go mod tidy`, then
  `GOOS=linux GOARCH=arm64 go list -deps` for the modules that really provide compiled packages ("built"), and
  `go list -m all` for the size of the graph. Versions of dependencies are the minimums the candidate asks for
  (MVS); in NMB's `go.mod` they would be raised to the current releases (`golang.org/x/net v0.62.0`,
  `golang.org/x/sys v0.50.0`, `golang.org/x/sync v0.25.0`, `golang.org/x/crypto v0.58.0`).
- **Vulnerabilities:** `govulncheck -scan package` (v1.1.3 found on the PC, not the gate's pinned v1.9.0) in each
  scratch module: no finding in any imported package of any candidate. Module-level findings exist only in the old
  `golang.org/x/net`, `golang.org/x/sys`, `golang.org/x/crypto` minimums (and `cilium/ebpf v0.4.0` / `v0.8.1` for the
  `hujun-open` modules); all are fixed by the current x/ releases, except GO-2026-5932 in `golang.org/x/crypto
  v0.58.0`, which concerns only `golang.org/x/crypto/openpgp` (not imported by any candidate; source
  `https://vuln.go.dev/ID/GO-2026-5932.json`, read 2026-11-11).
- **Vulnerabilities, re-run (synthesis, 2026-11-11):** the same scratch modules scanned again with the gate's
  pinned `govulncheck` v1.9.0 (`GOTOOLCHAIN=go1.27.4`, `GOOS=linux GOARCH=arm64 CGO_ENABLED=0`, `-scan package`):
  "No vulnerabilities found" for every row of this file (rows 1-10, 12-14, 16-20, 22 and the rejected
  `etherconn`).
- No personal data, no box data and no project findings went into any request.

Abbreviations: **BUILD IN** = compiled into `nmbd`; **RUN** = a separate program in the image that `nmbd` starts or
talks to (command line, socket, file); **own** = NMB's own code. "Notice" = keep the copyright line and licence text
with the binary's documentation (the image's licences folder and the about page of 6B.3A).

## Notes

- **Linux UAPI headers.** `golang.org/x/sys` and the netlink libraries carry constants and structures generated from
  the kernel's UAPI headers (`GPL-2.0 WITH Linux-syscall-note`). The note exempts programs that use the kernel
  through these interfaces; the libraries' own licences (BSD-3-Clause, MIT, Apache-2.0) are the ones that apply.
- **Apache-2.0 and GPL-2.0-only.** Rows 3, 8, 20 (and `safchain/ethtool`, `vishvananda/netns`) are Apache-2.0. Any
  open licence for NMB except GPL-2.0-only stays possible with them; if the owner ever wants GPL-2.0-only, rows 3 and
  8 would have to be replaced (row 22 for 3; for 8 there is no MIT nftables library of the same scope).
- **Pins.** Row 10 has no release tag at all (pseudo-versions only); rows 6, 7, 8, 17 are pre-1.0. A pin must name
  the exact pseudo-version and be raised on purpose.
- **Old dependency minimums.** Rows 3, 8, 14 ask for x/sys and x/net versions from 2023-2024; MVS in NMB's `go.mod`
  raises them, which is what clears the module-level govulncheck findings.
